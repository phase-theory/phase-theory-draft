MATHEMATICS OF COMPUTATION AS GEOMETRY

A Foundational Theory of Computational Space, Paths, Complexity, and Geometric Obstruction

Abstract

Computer science conventionally represents computation operationally:

[
x\mapsto f(x).
]

A program transforms an input into an output through a sequence of elementary operations. Complexity theory then asks how many resources are required to perform that transformation.

A deeper mathematical perspective is possible.

Instead of treating computation primarily as an operation acting on data, one may regard computation as a trajectory through a structured space of computational states:

[
X_0
\rightarrow
X_1
\rightarrow
\cdots
\rightarrow
X_n.
]

The fundamental object is then not merely the function (f), but a computational geometry

[
\boxed{
\mathcal C

(\mathcal X,\mathcal R,\mathcal T,\mathcal A,\mathcal G)
}
]

consisting of a state space (\mathcal X), admissible computational relations (\mathcal R), transition structure (\mathcal T), algorithmic equivalences (\mathcal A), and an induced geometric structure (\mathcal G).

Within such a framework, computational complexity can be interpreted geometrically. A computation becomes a path; time complexity becomes path length under a chosen computational metric; parallel complexity becomes geometric depth; communication complexity becomes a constrained distance; space complexity becomes a volume or dimensional occupancy measure; circuit complexity becomes geodesic distance in a circuit-state manifold or graph; irreversible computation becomes directed geometry; and computational hardness becomes a geometric obstruction to reaching a target region under admissible transformations.

The central proposal is therefore:

[
\boxed{
\text{computation}
\longrightarrow
\text{state space}
\longrightarrow
\text{transition geometry}
\longrightarrow
\text{computational distance}
\longrightarrow
\text{complexity}.
}
]

The framework synthesizes established mathematical ingredients from computational complexity, automata theory, graph theory, geometric group theory, circuit complexity, category theory, optimization, information geometry, quantum information, dynamical systems, and discrete geometry. It does not claim that these fields currently constitute one accepted theory. Rather, it proposes a common foundational language in which computation is treated as geometry generated by admissible transformations.

The deepest question is:

[
\boxed{
\text{What geometric properties of computational state space determine what can be computed, how efficiently it can be computed, and what transformations are intrinsically difficult?}
}
]

2. The Central Question

The ordinary computational question is:

[
\boxed{
\text{What function does the computation implement?}
}
]

The geometric question is:

[
\boxed{
\text{What space does computation inhabit, and what geometry does its allowed transformation system induce?}
}
]

The two questions are related but not equivalent.

Two algorithms can compute the same function:

[
f_1=f_2,
]

while following very different trajectories:

[
\gamma_1\neq\gamma_2.
]

Their computational costs can differ dramatically.

Thus the function alone does not determine the computational geometry.

[

[
\mathcal T

{T_\alpha}.

The pair

[

4. From Transitions to Relations

The transition system defines a relation

[

[

The graph is already a discrete geometry.

Vertices represent states.

Edges represent elementary transformations.

Paths represent computations.

7. Computational Distance

Suppose each elementary transition has cost

[
w(T)\geq0.
]

Define the computational distance

[
\boxed{
d_{\mathcal C}(x,y)

\inf_{\gamma:x\rightarrow y}
\sum_{T\in\gamma}w(T).
}
]

This is the shortest-path distance in the computational transition geometry.

If every transition costs one unit,

[
w(T)=1,
]

then

[
d_{\mathcal C}(x,y)
]

is the minimum number of computational steps required to transform (x) into (y).

This gives the first central identification:

[
\boxed{
\text{time complexity}
\sim
\text{computational path length}.
}
]

The equivalence is exact only after specifying the computational model.

[

10. Computational Geometry as a Metric Space

If the induced distance satisfies

[
d(x,y)=d(y,x),
]

then the computational state space can become a metric space.

However, ordinary computation is frequently irreversible.

One may have:

[
x\rightarrow y
]

without

[
y\rightarrow x.
]

Thus the natural structure may instead be a directed metric, quasi-metric, or weighted directed graph.

This distinction is foundational.

11. Directed Computational Geometry

Define

[
d^+(x,y)

\inf_{\gamma:x\rightarrow y}
L(\gamma).
]

Generally,

[
d^+(x,y)
\neq
d^+(y,x).
]

This asymmetry measures computational irreversibility.

If

[
d^+(x,y)<\infty,
\qquad
d^+(y,x)=\infty,
]

then (y) is computationally reachable from (x) but not conversely.

The geometry therefore contains a causal structure:

[
\boxed{
x\prec_{\mathcal C}y
\iff
d^+(x,y)<\infty.
}
]

24. Computational Curvature

A central question is whether complexity has curvature.

Suppose a computational metric

[
g_{ij}(x)
]

exists.

Then define the Levi-Civita connection

[
\Gamma^k_{ij}

\frac12g^{k\ell}
\left(
\partial_i g_{j\ell}
+
\partial_j g_{i\ell}

\partial_\ell g_{ij}
\right).
]

The curvature tensor is

[
R^k{}_{\ell ij}.
]

Curvature measures deviation from locally flat computational geometry.

The interpretation is:

[
\boxed{
\text{computational curvature}

\text{nonuniformity of transformation cost}.
}
]

This requires an actual differentiable metric realization; it is not automatic for arbitrary computational systems.

25. Curvature as Algorithmic Difficulty
